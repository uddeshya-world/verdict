# Threat model (v0.1 design)

This is the Phase-1 threat-model deliverable scoped to the code that exists today, plus the threats the design notes assign to later components. It is a design document. It is not an OWASP ASVS assessment, not a penetration test, and not a statement of compliance with any control framework.

Method: assets, trust boundaries, and abuse cases, each marked **implemented** or **planned / not present**.

## System under consideration

An operator runs `verdict` on a machine they control, against a pack file and a snapshot file, and receives a JSON report and an OpenVEX document. There is no daemon, no account, and no remote endpoint.

## Assets

| Asset | Why it matters | In v0.1 |
| --- | --- | --- |
| Verdict output | A wrong `not_affected` can close a real exposure. A wrong `exploitable` wastes response time. The first is treated as the worse failure | Produced locally |
| Snapshots | An inventory of versions, config, and exposure. Sensitive if it describes a real environment | Caller files. Examples are synthetic |
| Packs | A malicious or mistaken pack can encode a false precondition | Data, linted, not signed |
| Host running the CLI | Compromise of this host can change inputs or outputs | Out of scope of the tool; no privilege boundary is claimed |

## Trust boundaries

1. **Operator → CLI.** The operator can pass any file. The CLI's job is to refuse malformed packs and to apply the verdict rules, not to authenticate the operator.
2. **Snapshot → engine.** Facts are untrusted claims. See `docs/trust-boundary.md`. **Implemented:** non-`caller_asserted` trust labels are rejected; inferred facts do not falsify; confidence is not raised; the report repeats the unverified label.
3. **Pack → engine.** Packs are untrusted data. **Implemented:** closed set of check types, no execution, structural limits. **Not implemented:** signatures, reviewer keys, customer re-signing.
4. **CLI → network.** **Implemented:** the drill path has no dialer. `internal/netpolicy` denies every address unless a future caller passes an allowlist. **Not implemented:** an OS-level egress firewall, which this user-space process cannot install by itself.
5. **Tool → production systems.** **Implemented by absence:** no probe and no sandbox. The CLI does not connect to hosts. `scripts/collect-host.sh` is a separate read-only shell script that the operator runs on a host, or pipes over their own ssh session, and the CLI only reads the JSON it printed. The tool cannot reach production unless the operator uses it as a generic program outside these commands.

## Abuse cases

| ID | Abuse | Consequence | v0.1 response |
| --- | --- | --- | --- |
| A1 | Snapshot omits a vulnerable package and marks inventory complete at high confidence | False `not_affected` on a reviewed pack, if every other proof leaf is also strict | **Accepted residual.** Authenticity is outside the engine. Draft packs still cannot emit `not_affected`. Documented in the trust boundary |
| A2 | Snapshot sets confidence to `confirmed` without having observed anything | Same as A1 | **Accepted residual.** Same documentation. The field is caller-asserted |
| A3 | Distro package version is sorted against an upstream range and declared fixed, or one advisory clears a package it does not name | The common backport false-negative, and a false `not_affected` from an asset-wide fact | **Implemented:** `deb` / `rpm` / `apk` never take the version-sort branch. An advisory applies only when its `purl` equals that package. `import advisories` resolves a row to exact inventory package URLs: type, namespace, name, and version (epoch folded) must match, `arch`/`upstream` are ignored, and a `distro` on the row must equal the package's, so a 22.04 row never lands on a 24.04 package. An unmatched row fails the import unless `--allow-unmatched` drops it, and two rows with different values on one package fail. **Residual:** a row with no `distro` matches any distro with that exact version string. Values are `affected`, `fixed`, and `not_affected` (never vulnerable, which is not `fixed`). A missing or unscoped fact stays unknown. An in-range non-distro package stays true |
| A4 | Absent config key is filled with a vendor default that clears the finding | False `not_affected` | **Implemented:** absent facts are unknown |
| A5 | Stale "we patched this" fact | False `not_affected` after drift | **Implemented:** observations outside `evidence_max_age`, or with `expires_at` at or before evaluation time, become unknown. A future `observed_at` is also unusable |
| A6 | Draft or single-reviewer pack used to close findings | False confidence in an unreviewed encoding | **Implemented:** `not_affected` requires status `reviewed` and two distinct reviewer strings, and a ceiling of at least high. Repository policy additionally forbids non-synthetic reviewed packs in-tree |
| A7 | `any_of` false because one branch is false and another is unknown | Kleene value is unknown, but a naive "any false leaf" walk would say not affected | **Implemented:** disjunctions require every branch |
| A8 | Negated mitigation counted with the wrong polarity | Mitigation present treated as vulnerable, or mitigation absent treated as proof of safety | **Implemented:** `not` flips polarity; tests cover nested `not` / `all_of` / `any_of` |
| A9 | Two falsifying branches with different OpenVEX justifications | A single guessed justification misstates why | **Implemented:** mixed justifications stay `needs_review` |
| A10 | Unknown exposure labeled not affected, internal-only labeled not affected, or an unlisted zone treated as trusted-only | Understates reachability, or drops a P0 to internal-only | **Implemented:** exposure never selects `not_affected`. Zones come from a site policy, not the pack. Unknown exposure on a true tree, including a missing policy or a zone in neither list, is `exploitable` with `exposure_uncertainty`. Internal-only, meaning every usable zone is in the policy's `trusted_zones`, is `vulnerable_not_exposed` and OpenVEX `affected` |
| A11 | YAML anchor bomb or unknown field smuggles a check | Parser DoS or silent ignore | **Implemented:** aliases rejected, node and depth limits, duplicate keys rejected, unknown fields and check kinds rejected |
| A12 | Pack contains a shell command or probe and the CLI runs it | Remote code execution via untrusted pack | **Implemented:** no such field; probes are not representable |
| A13 | CLI phones home with inventory | Data leaves an air-gapped host | **Implemented** on the current command set: no dial. A test walks production imports |
| A14 | Demo snapshot is mistaken for a real assessment | Wrong operational decision | **Implemented** in documentation and in `evidence_trust`. Examples use `lab-` and `syn-` ids |
| A15 | Malicious or swapped pack in transit to the air-gapped side | Systematic false `not_affected` | **Partial.** `verdict bundle` signs a manifest of SHA-256 hashes with Ed25519. `bundle verify`/`install` and `drill --kb` reject a bad signature, an unlisted, missing, duplicate, non-regular, hidden, or traversing member, and a key_id mismatch, and re-verify the stored tar on every drill. `drill --kb` also requires the signed kb_version to equal the install directory name, so a validly signed older bundle copied over an install is refused. A whole install directory swapped for an older one is not detected (no freshness or monotonic-version check). One trusted key per invocation; no key rotation, revocation, or transparency log. A pack passed by `--pack` path is still unsigned input. A signed pack that is wrong is still wrong: signing proves origin, not correctness |
| A16 | Tool database of exploitable hosts is stolen | Map of weaknesses | **Not applicable.** No database is implemented. Reports written to disk have the sensitivity of their inputs; the CLI does not encrypt them |
| A17 | Secrets in a snapshot land in the report | Disclosure via the JSON the operator asked to write | **Partial.** The engine copies evidence ids and fact values that a check compared, and it does not have a secret scanner. Do not put secrets in snapshots. There is no log file |
| A18 | Dependency confusion or a compromised module at build time | Malicious binary | **Partial.** `go.sum` pins modules for this commit. There is no signed release and no SLSA provenance |
| A19 | `time.Now` makes two runs disagree or hides staleness | Non-reproducible audit | **Implemented:** evaluation time is a required explicit input |
| A20 | Active exploit or "confirmation" probe against production | Outage or compromise, and a policy violation for this project | **Implemented by absence.** No probe type, no sandbox, no production target flag |
| A21 | Crafted archive passed to `import jar`: zip bomb, header that understates size, deep nesting, huge entry count, or `../` names | Memory or CPU exhaustion, or a write outside the working tree | **Implemented:** archives are read in memory only and never extracted. Nesting depth 4, 200,000 entries, 64 MiB per entry, and 512 MiB total uncompressed (also the cap on each input file) are enforced. The declared size is checked and the actual stream is capped, so a lying header cannot inflate past the limit. Absolute, drive-letter, backslash, NUL, and `..` names refuse the import. Peak memory is roughly the inputs plus the nested archives held at once, bounded by the total cap |
| A22 | Shaded or stripped jar hides log4j-core coordinates, or a log4j-core jar sits on a classpath archive that was not passed | `JndiLookup` reported absent, or a version guessed, leading to a false `not_affected` | **Implemented:** the class is `present` wherever it is found. `absent` needs an identified log4j-core copy holding other log4j-core classes, and no unidentified log4j-core classes elsewhere. Otherwise the fact is omitted (unknown). A copy without coordinates is skipped, which also refuses `--complete`. `absent` covers only the archives passed, so a log4j-core jar elsewhere on the classpath (for example a Tomcat `lib` directory) would be missed. `absent` is therefore `medium`, below the `not_affected` bar, unless the operator passes `--complete` to assert that every classpath archive was included. A test applies a reviewed bar in memory and checks that a non-complete import never yields `not_affected`. **Residual:** `--complete` is an operator claim the tool cannot verify (see A1). A relocation that renames the whole package is not recognized as log4j-core |
| A23 | kubectl JSON is edited, partial, or from another cluster | Wrong inventory, exposure, or admission-webhook fact for a Kubernetes workload | **Partial.** `import k8s` output is caller-asserted like any snapshot; the importer cannot tell whether the operator's export was complete or genuine. It fails toward exposure: inventory is never complete, a webhook fact is written `false` only when every webhook object resolves, none reaches the controller, and every controller container has an explicit argv that never mentions `validating-webhook` (a `sh -c` wrapper or an image-default entrypoint leaves it unknown), a digest-only or mirrored ingress-nginx image gets no version, and a Service type without a zone flag is `unknown`. **Accepted residual:** the ingress-nginx version comes from the image tag, which trusts that `registry.k8s.io` tags are immutable. The `pkg:oci` package keeps the digest as its version when the reference has one, so pin controller images by digest and record `advisory.cve_2025_1974.status` on that package URL for rebuilt images |
| A24 | NetworkPolicy read as proof a port is unreachable | Exposure narrowed by a policy that a CNI may not enforce, or that another policy widens | **Implemented by absence.** NetworkPolicy objects are counted and ignored. Exposure from Services, Ingresses, and declared container ports is only ever widened. `cluster-internal` is a zone the site policy must classify |
| A25 | `collect-host.sh` output is edited, forged, or produced on a different host before `import host` | Facts marked `observed` and `high` that nobody observed, up to a false `not_affected` on a reviewed pack | **Accepted residual**, same as A1/A2. The document is caller-asserted. There is no collector identity or signature. **Implemented:** unknown fields and unknown fact keys are rejected, each fact value is checked against a closed set, the evidence id is a hash of the input bytes so a report points at one exact document, and `complete` stays false unless `--complete` is passed. `--complete` is refused when any package line was unparsed or a package manager failed |
| A26 | Collector reports a negative it could not see: "sshd not listening" without root, "no socket activation" while an activator holds tcp/22, or a default `LoginGraceTime` | False `not_affected` on a reviewed pack | **Implemented:** facts are omitted rather than guessed. `process.listening.sshd` is false only when every listening socket's owner was visible. `service.socket_activation.sshd` is false only when systemd's `ssh.socket` and `sshd.socket` are determinately absent or disabled (or systemd is not running), inetd/xinetd do not name sshd, and tcp/22 is not held by anything but sshd. `LoginGraceTime` comes from `sshd -T` or a value written in `sshd_config` and its `Include` files before the first `Match`, and is otherwise omitted. Sockets that were seen but not parsed make the socket table unobserved. Container tests cover root, non-root, sshd stopped, inetd, and a read-only root filesystem. **Residual:** activators other than systemd, inetd, and xinetd are not enumerated, though they would still hold tcp/22 and block the false value |
| A27 | Listening port treated as reachable, or collector run leaks secrets or changes the host | Overstated or invented exposure, disclosure, or an outage | **Implemented:** exposure is written only from `--reachable-from`, the operator's statement, and without it exposure stays unknown and fails closed (A10). The script reads os-release by parsing it, never by sourcing it, reads no private keys, `/etc/shadow`, or environment values, prints only selected fields, and writes nothing but stdout. **Residual:** `ldd` and `sshd -T` execute the installed sshd binary's loader or config parser, so a tampered sshd is outside this boundary |

## Planned controls (not built)

These appear in the design notes and are recorded so readers do not assume they exist:

- Customer trust roots, key rotation and revocation, re-signing, OCI distribution
- Collector identity or signing. `scripts/collect-host.sh` is read-only, but its output is unsigned and caller-asserted (A25)
- Encryption at rest, authentication, authorization, audit log
- SBOM and provenance for the Verdict binary itself
- Sandbox isolation for any future confirmatory probe
- A benchmark suite with a measured false-`not_affected` rate on real images

No item above is "partially certified".

## Out of scope

Physical access to the operator workstation, malicious Go toolchain, and vulnerabilities in third-party products that the draft packs describe. The draft packs are not detection signatures and are not safe to treat as a scanning policy by themselves.
