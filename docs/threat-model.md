# Threat model (v0.1 design)

This is the Phase-1 threat-model deliverable scoped to the code that exists today, plus the threats the design notes assign to later components. It is a design document. It is not an OWASP ASVS assessment, not a penetration test, and not a statement of compliance with any control framework.

Method: assets, trust boundaries, and abuse cases, each marked **implemented** or **planned / not present**.

## System under consideration

An operator runs `verdict` on a machine they control, against a pack file and a snapshot file, and receives a JSON report and an OpenVEX document. There is no daemon, no account, and no remote endpoint.

## Assets

| Asset | Why it matters | In v0.1 |
| --- | --- | --- |
| Verdict output | A wrong `not_affected` can close a real exposure. A wrong `exploitable` wastes response time. The first is treated as the worse failure | Produced locally |
| Snapshots | An inventory of versions, config, and exposure. Sensitive if it describes a real environment | Caller files. Examples are synthetic |
| Packs | A malicious or mistaken pack can encode a false precondition | Data, linted, not signed |
| Host running the CLI | Compromise of this host can change inputs or outputs | Out of scope of the tool; no privilege boundary is claimed |

## Trust boundaries

1. **Operator → CLI.** The operator can pass any file. The CLI's job is to refuse malformed packs and to apply the verdict rules, not to authenticate the operator.
2. **Snapshot → engine.** Facts are untrusted claims. See `docs/trust-boundary.md`. **Implemented:** non-`caller_asserted` trust labels are rejected; inferred facts do not falsify; confidence is not raised; the report repeats the unverified label.
3. **Pack → engine.** Packs are untrusted data. **Implemented:** closed set of check types, no execution, structural limits. **Not implemented:** signatures, reviewer keys, customer re-signing.
4. **CLI → network.** **Implemented:** the drill path has no dialer. `internal/netpolicy` denies every address unless a future caller passes an allowlist. **Not implemented:** an OS-level egress firewall, which this user-space process cannot install by itself.
5. **Tool → production systems.** **Implemented by absence:** no probe and no sandbox. The CLI does not connect to hosts. `scripts/collect-host.sh` is a separate read-only shell script that the operator runs on a host, or pipes over their own ssh session, and the CLI only reads the JSON it printed. The tool cannot reach production unless the operator uses it as a generic program outside these commands.

## Abuse cases

| ID | Abuse | Consequence | v0.1 response |
| --- | --- | --- | --- |
| A1 | Snapshot omits a vulnerable package and marks inventory complete at high confidence | False `not_affected` on a reviewed pack, if every other proof leaf is also strict | **Accepted residual.** Authenticity is outside the engine. Draft packs still cannot emit `not_affected`. Documented in the trust boundary |
| A2 | Snapshot sets confidence to `confirmed` without having observed anything | Same as A1 | **Accepted residual.** Same documentation. The field is caller-asserted |
| A3 | Distro package version is sorted against an upstream range and declared fixed, or one advisory clears a package it does not name | The common backport false-negative, and a false `not_affected` from an asset-wide fact | **Implemented:** `deb` / `rpm` / `apk` never take the version-sort branch. An advisory applies only when its `purl` equals that package (see A30 for spellings). `import advisories` resolves a row to exact inventory package URLs: type, namespace, name, and version (epoch folded) must match, `arch`/`upstream` are ignored, and a `distro` on the row must equal the package's, so a 22.04 row never lands on a 24.04 package. An unmatched row fails the import unless `--allow-unmatched` drops it, except that a row which matches no package exactly but names an inventory package under case folding or a lookalike skeleton (`OpenSSH-Server` for `openssh-server`) is always an error naming both purls. Two rows with different values on one package fail, and so do two rows for one asset and key that fold to the same package identity and disagree, matched or not. **Residual:** a row with no `distro` matches any distro with that exact version string. Values are `affected`, `fixed`, and `not_affected` (never vulnerable, which is not `fixed`). A missing or unscoped fact stays unknown. An in-range non-distro package stays true |
| A4 | Absent config key is filled with a vendor default that clears the finding | False `not_affected` | **Implemented:** absent facts are unknown |
| A5 | Stale "we patched this" fact | False `not_affected` after drift | **Implemented:** observations outside `evidence_max_age`, or with `expires_at` at or before evaluation time, become unknown. A future `observed_at` is also unusable |
| A6 | Draft or single-reviewer pack used to close findings | False confidence in an unreviewed encoding | **Implemented:** `not_affected` requires status `reviewed` and two distinct reviewer strings, and a ceiling of at least high. Repository policy additionally forbids non-synthetic reviewed packs in-tree |
| A7 | `any_of` false because one branch is false and another is unknown | Kleene value is unknown, but a naive "any false leaf" walk would say not affected | **Implemented:** disjunctions require every branch |
| A8 | Negated mitigation counted with the wrong polarity | Mitigation present treated as vulnerable, or mitigation absent treated as proof of safety | **Implemented:** `not` flips polarity; tests cover nested `not` / `all_of` / `any_of` |
| A9 | Two falsifying branches with different OpenVEX justifications | A single guessed justification misstates why | **Implemented:** mixed justifications stay `needs_review` |
| A10 | Unknown exposure labeled not affected, internal-only labeled not affected, or an unlisted zone treated as trusted-only | Understates reachability, or drops a P0 to internal-only | **Implemented:** exposure never selects `not_affected`. Zones come from a site policy, not the pack. Unknown exposure on a true tree, including a missing policy or a zone in neither list, is `exploitable` with `exposure_uncertainty`. Internal-only, meaning every usable zone is in the policy's `trusted_zones`, is `vulnerable_not_exposed` and OpenVEX `affected` |
| A11 | YAML anchor bomb or unknown field smuggles a check | Parser DoS or silent ignore | **Implemented:** aliases rejected, node and depth limits, duplicate keys rejected, unknown fields and check kinds rejected |
| A12 | Pack contains a shell command or probe and the CLI runs it | Remote code execution via untrusted pack | **Implemented:** no such field; probes are not representable |
| A13 | CLI phones home with inventory | Data leaves an air-gapped host | **Implemented** on the current command set: no dial. A test walks production imports |
| A14 | Demo snapshot is mistaken for a real assessment | Wrong operational decision | **Implemented** in documentation and in `evidence_trust`. Examples use `lab-` and `syn-` ids |
| A15 | Malicious or swapped pack in transit to the air-gapped side | Systematic false `not_affected` | **Partial.** `verdict bundle` signs a manifest of SHA-256 hashes with Ed25519. `bundle verify`/`install` and `drill --kb` reject a bad signature, an unlisted, missing, duplicate, non-regular, hidden, or traversing member, and a key_id mismatch, and re-verify the stored tar on every drill. `drill --kb` also requires the signed kb_version to equal the install directory name, so a validly signed older bundle copied over an install is refused. `drill --kb` computes the rollback floor from signed data: it verifies every `kb/<version>/bundle.tar` under the knowledge-base root with the trusted key and takes the newest signed `created_at` (see A37). It refuses an older version unless `--allow-older-kb` is passed. A bundle whose `created_at` is more than 5 minutes after the wall clock is refused as forged or clock-skewed; one created after the snapshot's evaluation time is allowed (re-checking an older snapshot with newer knowledge) with a stderr note, and the report records both times. `--max-kb-age` refuses one older than the given age before the evaluation time. The report records the bundle's `kb_version`, `key_id`, and `created_at` from the signed manifest, and `--kb-version` cannot override them. `drill --kb` reads every OSV record in each bundle file, the same as `drill --osv`. **Residual:** the floor is only as high as the signed bundles still installed (A37); `--max-kb-age` is opt-in, staleness is measured against the snapshot's caller-asserted evaluation time, and the future check trusts the local wall clock (the one clock read, in `internal/cli/clock.go`). One trusted key per invocation; no key rotation, revocation, or transparency log. A pack passed by `--pack` path is still unsigned input. A signed pack that is wrong is still wrong: signing proves origin, not correctness |
| A16 | Tool database of exploitable hosts is stolen | Map of weaknesses | **Not applicable.** No database is implemented. Reports written to disk have the sensitivity of their inputs; the CLI does not encrypt them |
| A17 | Secrets in a snapshot land in the report | Disclosure via the JSON the operator asked to write | **Partial.** The engine copies evidence ids and fact values that a check compared, and it does not have a secret scanner. Do not put secrets in snapshots. There is no log file |
| A18 | Dependency confusion or a compromised module at build time | Malicious binary | **Partial.** `go.sum` pins modules for this commit. There is no signed release and no SLSA provenance |
| A19 | `time.Now` makes two runs disagree or hides staleness | Non-reproducible audit | **Implemented:** evaluation time is a required explicit input |
| A20 | Active exploit or "confirmation" probe against production | Outage or compromise, and a policy violation for this project | **Implemented by absence.** No probe type, no sandbox, no production target flag |
| A21 | Crafted archive passed to `import jar`: zip bomb, header that understates size, deep nesting, huge entry count, or `../` names | Memory or CPU exhaustion, or a write outside the working tree | **Implemented:** archives are read in memory only and never extracted. Nesting depth 4, 200,000 entries, 64 MiB per entry, and 512 MiB total uncompressed (also the cap on each input file) are enforced. The declared size is checked and the actual stream is capped, so a lying header cannot inflate past the limit. Absolute, drive-letter, backslash, NUL, and `..` names refuse the import. Peak memory is roughly the inputs plus the nested archives held at once, bounded by the total cap |
| A22 | Shaded or stripped jar hides log4j-core coordinates, or a log4j-core jar sits on a classpath archive that was not passed | `JndiLookup` reported absent, or a version guessed, leading to a false `not_affected` | **Implemented:** the class is `present` wherever it is found. `absent` needs an identified log4j-core copy holding other log4j-core classes, and no unidentified log4j-core classes elsewhere. A `JndiLookup.class` under any other package, or a `jndi` entry in `Log4j2Plugins.dat` that names a non-canonical class (or an unparseable cache that mentions jndi), also rules out `absent`. Otherwise the fact is omitted (unknown). Nested `.zip` (and other zip-based) archives are scanned under the A21 caps, and any other archive-like entry (`.tar`, `.tar.gz`, `.7z`, `.jmod`, and similar) is listed as skipped. A copy without coordinates is skipped, which also refuses `--complete`. `absent` covers only the archives passed, so a log4j-core jar elsewhere on the classpath (for example a Tomcat `lib` directory) would be missed. `absent` is therefore `medium`, below the `not_affected` bar, unless the operator passes `--complete` to assert that every classpath archive was included. A test applies a reviewed bar in memory and checks that a non-complete import never yields `not_affected`. **Residual:** `--complete` is an operator claim the tool cannot verify (see A1). A relocation that renames both the package and the `JndiLookup` class, and drops or rewrites the plugin cache, is not recognized. A jar renamed to an extension outside the scanned and skipped lists is not opened. An unrelated class that happens to be named `JndiLookup` makes the fact unknown, which fails toward `needs_review` |
| A23 | kubectl JSON is edited, partial, or from another cluster | Wrong inventory, exposure, or admission-webhook fact for a Kubernetes workload | **Partial.** `import k8s` output is caller-asserted like any snapshot; the importer cannot tell whether the operator's export was complete or genuine. It fails toward exposure: inventory is never complete, a webhook fact is written `false` only when every webhook object resolves, none reaches the controller, and every controller container has an explicit argv that never mentions `validating-webhook` (a `sh -c` wrapper or an image-default entrypoint leaves it unknown), a digest-only or mirrored ingress-nginx image gets no version, and a Service type without a zone flag is `unknown`. **Accepted residual:** the ingress-nginx version comes from the image tag, which trusts that `registry.k8s.io` tags are immutable. The `pkg:oci` package keeps the digest as its version when the reference has one, so pin controller images by digest and record `advisory.cve_2025_1974.status` on that package URL for rebuilt images |
| A24 | NetworkPolicy read as proof a port is unreachable | Exposure narrowed by a policy that a CNI may not enforce, or that another policy widens | **Implemented by absence.** NetworkPolicy objects are counted and ignored. Exposure from Services, Ingresses, and declared container ports is only ever widened. `cluster-internal` is a zone the site policy must classify |
| A25 | `collect-host.sh` output is edited, forged, or produced on a different host before `import host` | Facts marked `observed` and `high` that nobody observed, up to a false `not_affected` on a reviewed pack | **Accepted residual**, same as A1/A2. The document is caller-asserted. There is no collector identity or signature. **Implemented:** unknown fields and unknown fact keys are rejected, each fact value is checked against a closed set, the evidence id is a hash of the input bytes so a report points at one exact document, and `complete` stays false unless `--complete` is passed. `--complete` is refused when any package line was unparsed or a package manager failed |
| A26 | Collector reports a negative it could not see: "sshd not listening" without root, "no socket activation" while an activator holds tcp/22, or a default `LoginGraceTime` | False `not_affected` on a reviewed pack | **Implemented:** facts are omitted rather than guessed. `process.listening.sshd` is false only when every listening socket's owner was visible. `service.socket_activation.sshd` is false only when systemd's `ssh.socket` and `sshd.socket` are determinately absent or disabled (or systemd is not running), inetd/xinetd do not name sshd, and tcp/22 is not held by anything but sshd. `LoginGraceTime` comes from `sshd -T` or a value written in `sshd_config` and its `Include` files before the first `Match`, and is otherwise omitted. Sockets that were seen but not parsed make the socket table unobserved. Container tests cover root, non-root, sshd stopped, inetd, and a read-only root filesystem. **Residual:** activators other than systemd, inetd, and xinetd are not enumerated, though they would still hold tcp/22 and block the false value |
| A27 | Listening port treated as reachable, or collector run leaks secrets or changes the host | Overstated or invented exposure, disclosure, or an outage | **Implemented:** exposure is written only from `--reachable-from`, the operator's statement, and without it exposure stays unknown and fails closed (A10). The script reads os-release by parsing it, never by sourcing it, reads no private keys, `/etc/shadow`, or environment values, prints only selected fields, and writes nothing but stdout. **Residual:** `ldd` and `sshd -T` execute the installed sshd binary's loader or config parser, so a tampered sshd is outside this boundary |
| A28 | Oversized snapshot file | Memory exhaustion while a drill or merge loads it, or a cap so low that a real estate cannot be assessed | **Implemented:** snapshot files are read through a limit of `--max-snapshot-bytes` (default 256 MiB, about 10k real syft hosts at roughly 22 KB of RSS per asset) on `drill`, `snapshot merge`, `import advisories`, and `pack test`; a regular file over the cap is refused from its size before any read (a 600 MB file went from about 590 MiB peak RSS to about 17 MiB), and other sources are read through a `cap+1` limit. The cap must be 1 byte to 1 TiB, so a value near MaxInt64 can no longer wrap. Every snapshot writer (`merge`, `import cyclonedx|trivy|jar|host|k8s|advisories`) refuses output over the same cap; the error names the flag. **Residual:** the document is decoded in memory, not streamed, so peak memory scales with the cap the operator chooses |
| A29 | Inventory spells the component differently: `pkg:generic/OpenSSH`, a trailing space (`openssh%20`), `pkg:GENERIC/...`, a deb name in another case, or an alias such as `openssh-portable` | The package matches no pattern, counts as absent, and a complete inventory yields `component_not_present` and a false `not_affected` | **Implemented:** the purl type is case-insensitive and lowercased in the canonical form, so `pkg:GENERIC` is an exact match. Any other variant is in scope and unknown, never absent and never version-sorted: a name that is equal after percent-decoding, trimming, and case-folding, or equal with separators removed, under any type or namespace. The same applies to a generic package whose name tokens contain the pattern's (`openssh-portable`), a distro package that contains a distro pattern's tokens (`openssh-server-pam`), and any inventory package that an advisory fact for this CVE names. A purl-scoped advisory for this CVE that names a package missing from a complete inventory also blocks the absence proof. A variant resolves only through an observed advisory on that exact package URL. **Also implemented (run 3, N1/N2):** names are compared as `purl.Skeleton` forms (percent-decoded to a fixpoint, fullwidth ASCII and long s mapped to ASCII, Cyrillic and Greek lookalikes mapped to Latin), and any name that still holds a non-ASCII rune is related to every pattern, so it is unknown and never absent. For generic packages and distro-vs-distro, a squashed pattern name that is a substring of the squashed package name (`opensshd`, `openssh9`) is related, and so is the reverse when the pattern name has four or more characters. **Also implemented (A35):** a pack may declare `aliases` on a `package_version` check, so a name that shares no substring with the pattern (`pkg:generic/sshd` in the OpenSSH pack) is unknown, not absent. **Residual:** an alias the pack does not declare and that shares no substring with the pattern (`openbsd-ssh`, a vendor rename, a language-ecosystem package such as `pkg:npm/xz-...`) is still absent from the inventory alone; it is caught only where the pack lists a runtime fact in `absence_contradicted_by` (A32). Distro packages are not related to a generic pattern (`openssh-client` is not sshd), so a distro rename that drops the pattern's name is missed. A legitimate package with an unmapped non-ASCII name now blocks absence on that asset (needs_review), a deliberate false-positive cost. |
| A30 | Two advisory facts for one package disagree and are spelled differently (escaped epoch, qualifier order, name case) | Whichever fact came first decided the verdict, so a `fixed` placed first gave `not_affected` | **Implemented:** the engine reads every advisory fact whose package URL is canonically equal or case-folded equal to the inventory package. Any disagreement is unknown (`conflicting_advisory`) whatever the order. Agreeing facts use the weakest quality. An advisory on a spelling variant only is not applied (`advisory_purl_variant`). Load rejects a byte-identical key and purl twice, but accepts different spellings: merged advisory sources produce them, and one asset's conflict should be `needs_review` with both evidence ids rather than a failed fleet drill. Bench cases cover both orders |
| A31 | OpenVEX statement names an unrelated package as the product | A downstream tool suppresses or annotates the wrong finding | **Implemented:** the product identifier is the caller's `primary_purl`, or else the single inventory package that exactly matches the pack's component or `package_version` patterns. With no match, or more than one, the statement has no purl identifier, only the asset URN |
| A32 | Inventory has no package that matches the component, but the host's own facts say the component runs (`process.listening.sshd=true`, socket activation, `process.sshd.links_liblzma=true`): an alias with no shared name (`sshd`, `ssh-server`) or an incomplete package list | A complete inventory yields `component_not_present` and a false `not_affected` on a host that is running the vulnerable service | **Implemented:** an optional `absence_contradicted_by: [fact keys]` on a `package_version` check. Before the engine returns an absence proof it scans every fact on the asset. A fact contradicts absence when its key equals a listed key, exactly or after `TrimSpace` and lowercasing (`Process.Listening.sshd`), with or without a purl, on any basis and whatever its age, and its value is anything other than `false` after `TrimSpace` and lowercasing. `true`, `True`, `yes`, `1`, `on`, `running`, ` true`, and an empty value all block. The result is unknown with reason `component_absent_but_in_use` and that fact's evidence id. Lint requires well-formed, unique keys (at most 16) and rejects the field on other check types. The OpenSSH pack lists `process.listening.sshd` and `service.socket_activation.sshd`; the xz pack lists `process.sshd.links_liblzma`. **Residual (run 4 M1):** it only helps when the caller supplies a fact under a listed key; arbitrary renamed keys (`sshd2`, `process.listening.openssh`, a typo) are not matched, and a host with no runtime facts and an alias name is still absent. Only a value that is `false` after normalisation never clears anything. |
| A33 | Operator-entered facts or exposure (`snapshot set-fact`, `set-exposure`, `apply`) are used to hand-craft a `not_affected`: an invented `libc.family=musl`, an exposure list that omits a zone, or an overwrite of a fact an importer observed | False `not_affected` (facts) or understated reachability (exposure) | **Implemented:** the default basis is `attested` at `medium`, and attested entries never meet the `not_affected` bar. `high` requires `observed`; `observed` requires an evidence file (its SHA-256 is the evidence id) and an explicit `observed_at` that is not after `evaluation_time`. No silent overwrite: replacing a fact with the same key and canonical package URL needs `--replace`, a `--purl` must equal an inventory package, and exposure can only add or widen zones unless `--replace` is passed. Batches are atomic. `inventory.complete` and `evidence_trust` are never edited. Output is re-validated and size-capped. Tests simulate a reviewed openssh pack: attested, low, medium, and stale musl facts do not give `not_affected`. **Residual:** verdict hashes the evidence file but cannot tell whether it proves the claim, or whether it exists outside this machine. An operator can still enter `observed` + `high` for something they never observed (A1, A2). Since A36 every edit also leaves an `edits` record on the asset (what was there, what replaced it), so `--replace` is no longer traceless; the record is itself caller-asserted and can be hand-edited out of the JSON |
| A34 | A fact value is a near-miss of the canonical one: `True`, `yes`, `1`, `on`, `running`, ` true`, or `Glibc`; or the fact key differs in case (`Process.Listening.sshd`) | An equals leaf compares strings exactly, so `service.socket_activation.sshd=True` reads as "not false" and falsifies the socket precondition, and `libc.family=Glibc` reads as "not musl". The result is a false `not_affected` on a host that runs the service (run 4 H3) | **Implemented:** `host_fact` equals leaves compare normalised values. A value equal to the expected one after `TrimSpace` and case folding, but not byte-equal, is unknown (`fact_value_not_canonical`). A non-boolean value against an expected `true` or `false` is unknown (`fact_value_not_boolean`). A value outside the closed set of a known key (`libc.family`: glibc, musl; the boolean collector keys: true, false) is unknown (`fact_value_out_of_domain`). The closed sets live in `internal/factkeys` and are shared with the host importer. A fact whose key matches the expected key only after folding is unknown (`fact_key_not_canonical`), not missing and not false. **Residual:** a free-form key with no closed set (`config.sshd.LoginGraceTime`) is still compared as given; a wrong but well-formed value of a known key (`musl` on a glibc host) is a caller lie, covered by the evidence trust model. |
| A35 | A package ships the component under a name the pack's patterns do not cover and name similarity does not reach (`pkg:generic/sshd` for OpenSSH), and the pack author knows it | The package matches no pattern, so a complete inventory yields `component_not_present` and a false `not_affected` (A29 residual) | **Implemented:** optional per-check `aliases: [purl patterns]` on `package_version`. An inventory package that matches an alias (exact, or `purl.Related` to it) and is not an exact component match is an extra: the check is unknown, absence is never proven, and the version is never sorted. Aliases never produce true or false: only exact component patterns and an observed advisory on the exact package URL do, as for any other related package. They cannot widen what matches the component, so they cannot create `affected` or `not_affected`, the OpenVEX product identifier ignores them, and `when_package` does not read them. Lint requires well-formed purl patterns (no version, qualifier, or subpath), no duplicates (case-insensitive), no alias equal to a component or check pattern, at most 32, and rejects the field on other check types. The content hash covers aliases (the decoded struct is hashed, and an empty list is omitted so packs without aliases keep their hash); changing one voids a review record. Bench cases `regresshion/alias-sshd-*` show an alias-only complete inventory is `needs_review` under the reviewed bar, where main gave `not_affected` / `component_not_present`. **Residual:** an alias is the pack author's claim from a cited source; a wrong alias only costs a `needs_review`, never a clear. A listed alias that is a client-only package would block absence on every host with that client, so only server-shipping names are listed. When an alias package carries an observed advisory on its exact URL, that advisory decides it like any related package |
| A36 | An operator edit (`snapshot set-fact`, `set-exposure`, `apply`, especially `--replace`) changes the evidence behind a verdict and later reports cannot tell: a reviewer reads a `not_affected` as importer-observed when a person typed the fact, or an observed "in use" fact was overwritten and nothing shows it | A `not_affected` or a narrowed exposure is trusted as collector evidence; the audit trail of a replaced fact is lost | **Implemented:** every edit appends one record to the asset's optional `edits` array: op, key or port/proto, package URL, old and new value or zones, old and new basis, `replaced`, `at`, `source`, and the evidence id. `at` is the `--observed-at` given or the snapshot `evaluation_time`; the clock is never read. `snapshot.Load` validates records with a closed field set (unknown fields refused). `snapshot merge` keeps them; importers never write them. The drill report marks each leaf whose evidence fact was operator-edited (`operator_edited`), gives the verdict `operator_edits: N`, and the stderr line shows `(operator-edited)`. An OpenVEX `not_affected` whose proof relies on an edited fact adds "relies on operator-edited evidence" to `impact_statement`. Reports of snapshots with no edits are byte-identical to before. Tests: records for add and replace, atomic batches, merge, malformed records refused, marked leaves. **Residual:** the marker is a flag, not a gate: an edited fact still decides under the A33 bar. A shared evidence id (the attested default `attested:operator-entry`) marks every leaf citing it, which over-flags rather than under-flags. Records live in the same caller-asserted file, so someone with write access can delete them (A1, A2) |
| A37 | Someone with write access to the knowledge-base root lowers or deletes the unsigned `kb/LATEST` rollback floor, then drills against an older signed bundle | A stale knowledge version is used silently, so packs or OSV records added since are missed and findings can be understated | **Implemented:** `drill --kb` does not read the floor from `LATEST`. It verifies every installed `kb/<version>/bundle.tar` (full signature and hash check; a bundle that fails, or whose signed kb_version differs from its directory name, is skipped with a stderr note) and takes the newest signed `created_at` as the floor. `LATEST` is a cache and a hint that can only raise the floor: a `LATEST` below the computed floor, or a missing one, is noted on stderr and the computed floor wins; where `LATEST` names a verified install the signed time replaces the recorded one. A malformed `LATEST` is still an error. `--require-floor` refuses unless at least one other verified bundle is installed, for operators who want strict monotonicity. At most 256 version directories are scanned. Cost: 5 installed bundles of 13.5 MB (5,003 OSV records each) took 0.18 s per drill against 0.06 s for one, so no verification cache exists and no trust state is written to disk. **Residual:** deleting a signed newer install lowers the floor, which is the same as never having installed it, and nothing offline can tell the difference (a `LATEST` that names a deleted version still raises the floor, but an attacker who removes both wins). A bundle swapped for an older signed one under the same directory name is caught by the kb_version check, not by the floor. Use append-only or immutable storage (a read-only mount, `chattr +i`, WORM media) for the knowledge-base root, and keep a copy of the newest bundle off the machine |

## Planned controls (not built)

These appear in the design notes and are recorded so readers do not assume they exist:

- Customer trust roots, key rotation and revocation, re-signing, OCI distribution
- Collector identity or signing. `scripts/collect-host.sh` is read-only, but its output is unsigned and caller-asserted (A25)
- Encryption at rest, authentication, authorization, audit log
- SBOM and provenance for the Verdict binary itself
- Sandbox isolation for any future confirmatory probe
- A benchmark suite with a measured false-`not_affected` rate on real images

No item above is "partially certified".

## Out of scope

Physical access to the operator workstation, malicious Go toolchain, and vulnerabilities in third-party products that the draft packs describe. The draft packs are not detection signatures and are not safe to treat as a scanning policy by themselves.
